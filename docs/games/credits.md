# Asset rights and credits

**The rule: no file ships in a game without a declared source and licence.
Prefer assets you generate in code or make yourself.** A procedural mesh, a
canvas texture or a synthesised sound needs no licence, no credit and no
download. Reach for someone else's file only when you can name where it came
from, who made it and the licence it is under.

`pnpm games:check <id>` enforces this. It reads `credits` in
`games/<id>/game.json`, scans the built folder, and fails the check (so
nothing is published) when a file is unaccounted for.

## What to do when you add a file

1. Made it yourself for this game (drawn, rendered, recorded, generated by
   your own code)? Add it to an own-made entry:

    ```json
    { "origin": "own", "files": ["preview.jpg", "sounds/*.ogg"] }
    ```

    Only say `own` when it is true. Output of a generator trained on or
    assembled from other people's work, a file "found online", or a file from
    another Oncyber folder is not own-made: credit where it came from.

2. Someone else's work? Add a full entry:

    ```json
    {
        "title": "Anton",
        "kind": "font",
        "files": ["fonts/Anton-Regular.ttf", "assets/Anton-Regular-*.ttf"],
        "author": "The Anton Project Authors",
        "source": "https://github.com/googlefonts/AntonFont",
        "license": "OFL-1.1",
        "licenseFile": "fonts/Anton-OFL.txt"
    }
    ```

3. Added an npm dependency? Every name in the game's `package.json`
   `dependencies` needs an entry with `"kind": "library"` and
   `"package": "<name>"`. It has no `files`: the library is inside the bundle.

4. Run `pnpm games:credits` (rewrites the games section of
   `THIRD_PARTY_NOTICES.md`), then `pnpm games:check <id>`.

| Field         | Meaning                                                                                                                                            |
| ------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `files`       | Paths in the built folder (`frontend/public/games/<id>/`). `*` matches within a folder (use it for hashed names), `**` across folders.             |
| `origin`      | `"own"`: made for this game. Then only `files` and an optional `note`.                                                                             |
| `title`       | What it is, as a visitor would read it in the credits.                                                                                             |
| `kind`        | `model`, `texture`, `image`, `audio`, `font`, `motion`, `library`, `data` or `other`.                                                              |
| `package`     | For a bundled library: its name in `dependencies`.                                                                                                 |
| `author`      | Who made it. If you cannot find out, you cannot ship it.                                                                                           |
| `source`      | The `https` page you took it from.                                                                                                                 |
| `license`     | An identifier from `games/licenses.json`.                                                                                                          |
| `licenseFile` | Path in the build of the licence text. Required when the licence asks for its text or notice to travel with the file (`"text": true` in the list). |
| `note`        | Anything a reader of the credits should know.                                                                                                      |

Put licence texts in `games/<id>/public/licenses/` (copy the file from the
package or the download, never retype it); the build copies them.

## What the check does

-   **Every file in the build needs a credit**, except code and markup
    (`.html`, `.js`, `.mjs`, `.css`, `.map`), plain documents (`.txt`, `.md`)
    and the reports the check writes. That includes `.json` (motion data is
    someone's work) and `.svg`. A file with binary content needs a credit
    whatever its name. `ASSET_UNCREDITED`
-   **Licences come from one allow list**, `games/licenses.json`: public
    domain and permissive licences only. `LICENSE_NOT_ALLOWED`
-   **Licence text ships when the licence asks for it** and is a real text
    file in the build. `LICENSE_TEXT_MISSING`, `LICENSE_FILE_MISSING`
-   **Dependencies are credited** and the credit's licence matches the
    package's own `package.json`. `LIBRARY_UNCREDITED`,
    `LIBRARY_LICENSE_MISMATCH`
-   **`THIRD_PARTY_NOTICES.md` is current.** `NOTICES_STALE`
-   Warnings do not fail the check: a credit that matches nothing
    (`CREDIT_UNUSED`), and a licence that is a recorded exception nobody has
    confirmed (`RIGHTS_UNCONFIRMED`). Both appear under `credits.warnings` in
    `check.json`.

If the check fails on a licence, do not rename the licence, mark the file
`own`, or edit `games/licenses.json` to get through. Replace the file with
one under an allowed licence, generate it instead, or stop and ask a person.

## Licences outside the list

Adding a licence to `allowed`, or an entry to `exceptions`, is a person's
decision. An exception names one game and one `LicenseRef-<name>` identifier
with the reason; until `confirmedBy` holds a name and date it is reported as
`RIGHTS_UNCONFIRMED` on every check and shown as "to be confirmed" in the
notices. The exceptions there today record files that shipped before this
rule; they are a list of open questions, not a precedent.

## Where credits show up

-   `frontend/public/games/<id>/credits.json`, written by the check. It is
    one of the release's files ([releases.md](releases.md)): the page reads
    it from wherever the game's frame loads, so a hosted release shows its
    own credits and licence texts.
-   The **Credits** button on the game's page
    (`frontend/features/games/GameCredits.tsx`). The page owns it, so a game
    cannot hide or change its credits.
-   The games section of `THIRD_PARTY_NOTICES.md`.

Code: `games/runtime/src/credits.ts` (rules, pure),
`scripts/games/credits.mjs` (the check stage and the notices generator),
`frontend/features/games/gameCredits.ts` (the page's reader).

## Not covered yet

Files a game fetches from the network at run time, and media embedded in
code as `data:` URLs, are not scanned. Avatars the visitor brings are theirs
and are not the game's assets.
